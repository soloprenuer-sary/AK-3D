## 1. Pricing formulas and typical Indian costs (FDM and resin)

### Takeaway
Cost-plus is the norm: (material grams x waste factor x price/g) + machine-hour cost (electricity + depreciation + maintenance) + labour/post-processing + setup, then a margin. Indian retail filament is roughly Rs 700-1,500/kg (PLA) and resin Rs 1,600-2,500/kg, while Indian services charge roughly Rs 3-11/g for FDM PLA (IamRapid lists Rs 6/g and a sample quote works out to about Rs 8/g incl. everything), and resin is typically priced per cm3 (Rs 30-40/cm3 at IamRapid) or Rs 8-15/g.

**Machine/overhead inputs (Zbotic, India-specific, vendor blog)**
- Filament cost = grams x waste factor x price/g (example 45 g x 1.10 x Rs 1.80); electricity = (avg W/1000) x hours x Rs/kWh; depreciation = printer price / lifespan hours (Rs 25,000 / 5,000 h = Rs 5/h); maintenance Rs 2,000-5,000/yr over ~1,000 print hours = Rs 2-5/h — [Zbotic cost guide](https://zbotic.in/3d-printing-costs-india-calculate-material-and-electricity/).

- Same source: material waste allowance 10-15% (20-25% while learning), time lost to failures/restarts 5-10% of print time, skilled labour rate Rs 300/h, local services charge roughly Rs 5-20/g of finished part. It states no profit margin.

**Plugin pricing models (what existing tools implement)**
- 3DPrint Lite: price = printer cost + material cost, computed by filament volume, weight or bounding-box volume; tiered pricing as `threshold:price` pairs (e.g. `0:0.5;200:0.4;400:0.3`); printability check only verifies the model fits the build tray — [3DPrint Lite](https://wordpress.org/plugins/3dprint-lite/).
- PrintPrice: material price/kg x density x margin tiers; optional bulk discounts, min price per part, setup fees, quality/turnaround tiers, post-processing add-ons; handling time at labour rate with caps; multi-colour 3MF gets a purge-waste allowance; resin pricing supported — [PrintPrice](https://wordpress.org/plugins/printprice-3d-calculator/).

### Inferences
- Defensible Indian benchmark: a 100 g PLA part should land around Rs 6-8/g (Rs 600-800 before GST) for an in-house shop with human handling; Rs 3-5/g quotes (Zbotic/3Ding) likely mean low-complexity parts on cheap fast machines with little labour, and the Rs 8/g effective rate in IamRapid's sample quote includes more handling/margin.
- Resin per ml: at ~Rs 1,600-2,500/kg and a typical resin density of roughly 1.1 g/ml (my assumption, not sourced), raw resin cost is about Rs 1.8-2.8/ml. Resin services price per cm3 at Rs 30-40, i.e. 10-20x raw material, because wash/cure consumables, FEP/vat wear, supports, and labour dominate.
- Recommended formula (derived from cited components):
  `Price = [ (grams x (1+waste) x Rs/g) + (hours x (elec + depreciation + maintenance) x (1+failure_time)) + labour_min/60 x Rs/h_labour + setup ] x (1+margin) x complexity x qty_discount x rush  (+ GST 18%)`
- Worked example, 100 g PLA part (assumptions: filament Rs 1,000/kg = Rs 1/g from the Rs 800-1,200 budget range; 10% waste; 9 h print time at ~11 g/h, which is my assumption for 0.2 mm/15-20% infill on a mid-range printer; 200 W avg at Rs 9/kWh; depreciation Rs 8/h; maintenance Rs 3/h; 7.5% time lost to failures; 30 min labour+support removal at Rs 300/h; Rs 50 setup; 50% markup):
  - Material: 100 x 1.10 x Rs 1 = Rs 110
  - Electricity: 0.2 kW x 9 h x Rs 9 = Rs 16.2; depreciation 9 x 8 = Rs 72; maintenance 9 x 3 = Rs 27 -> Rs 115.2 x 1.075 failure uplift = Rs 123.8
  - Labour/post-processing: 0.5 h x Rs 300 = Rs 150
  - Setup: Rs 50
  - Cost = Rs 433.8; with 50% markup = Rs 650.8 (~Rs 6.5/g, in line with IamRapid's Rs 6/g list price); + 18% GST (Rs 117) = ~Rs 768
- Complexity multipliers, rush fees (suggest +25/50/100% for 48h/24h/same-day), design rate (Rs 800-1,500/h per the ranges above) and quantity-discount tiers (use IamRapid's cited 20-30% at 50+, 40-50% at 500+ as a ceiling; for a small shop start with 5/10/15% at 5/10/25 pcs) are policy choices; no source gives an Indian standard for them.
- Handle the Rs 3-5/g competitor floor by setting a minimum order (Rs 200-500 is common) and a setup fee so small parts do not lose money.

### Gaps
- No reliable source for Indian ABS/ASA/PETG print-service per-gram prices distinct from PLA (only blog ranges, mostly "Rs 3-8/g ABS").
- No sourced figure for resin wash/IPA/cure consumables, FEP replacement, or MSLA depreciation per hour in India.
- No sourced figures for complexity multipliers, rush-fee percentages, or Indian industry-standard quantity-discount tables (the 20-30%/40-50% numbers are IamRapid's generic claim).
- Indian electricity tariffs and filament prices vary by state/seller and date; all price-tracker data is scraped, not official.

## 2. How instant quoting works technically (slicer vs mesh-volume, PHP/WordPress architecture, tools)

### Takeaway
Two tiers exist: geometric estimates (mesh volume x infill/shell factors, bounding box, surface area) that are instant but approximate, and real slicing with a headless slicer (PrusaSlicer/OrcaSlicer/CuraEngine) that reads time and grams from the output. Commercial WooCommerce plugins split the same way: Birlo uses a geometric estimator with optional local slicer, Slicepress and WP3DP use hosted/remote slicers, PrintPrice parses meshes in a cloud service. For a custom build, a small Python microservice (trimesh for validation/volume + slicer CLI for time/weight) called from WordPress is the cleanest fit; I found no sourced evidence about client-side three.js quoting.

### Cited Findings

**Slicer CLIs**
- PrusaSlicer CLI (Debian man page): `--export-gcode`/`-g` slices and exports G-code; `--info` writes model information to the console; `--load` loads config files (repeatable); `--output/-o`; `--datadir`; `--loglevel` 0-5; `--dont-arrange`; `--center`; `--scale`; `--export-stl`; `--repair` ("try to repair any non-manifold meshes", implicitly applied when slicing); `--slice/-s` slices as FFF or SLA depending on `printer_technology`; `--help-fff` lists all options — [PrusaSlicer man page](https://dyn.manpages.debian.org/trixie/prusa-slicer/prusa-slicer.1). The official GitHub wiki page "Command Line Interface" is the canonical reference per the README but I could not retrieve it.
- PrusaSlicer has no flag that prints time/weight; the usual method is to read comments in the exported G-code, e.g. `; filament used [g]`, `; filament used [mm]` and `; estimated printing time (normal mode) = ...`. With binary G-code (.bgcode) metadata sits in PRINTER_METADATA/PRINT_METADATA blocks so a plain grep may miss it — [Printago G-code article](https://printago.io/blog/gcode-filament-usage) (shows `; filament used [g] = 14.21, 4.25` per-slot format), [DEV Community wrapper script](https://dev.to/johalputt/slicing-what-is-in-3d-printing-and-why-it-matters-47fa), [Prusa forum thread](https://forum.prusa3d.com/forum/prusaslicer/how-to-get-duration-and-filament-usage-on-cli/), [fdm-price-calc on PyPI](https://pypi.org/project/fdm-price-calc/).
- PrusaSlicer Windows caveat: some CLI actions (e.g. `--duplicate`) reported not working on Windows 10/11 with 2.6 and 2.8.0; use `prusa-slicer-console.exe`; a forum user saw CLI output differ from GUI for multi-extruder prints — [Prusa forum](https://forum.prusa3d.com/forum/prusaslicer/prusaslicer-cli-command-line-actions-broken-on-windows).
- OrcaSlicer CLI: `--slice 0` (all plates) or `i`; `--export-3mf`, `--export-slicedata dir`, `--load-slicedata`, `--export-stl`, `--export-settings`, `--min-save`, `--no-check`, `--info` (prints object/instance counts, dimensions, etc., on the unrepaired model; the page does not say it reports manifold status or volume), `--mtcpp` (max triangles per plate, default 1,000,000), `--mstpp` (max slicing time per plate, default 300 s), `--pipe` for progress — [OrcaSlicer CLI actions](https://www.orcaslicer.com/wiki/cli/cli_actions). Pattern: `orca-slicer model.3mf --load-settings "process.json;printer.json" --load-filaments filament.json --slice 0 --export-3mf out.3mf`; settings order matters (machine first, then process); CLI values override loaded files which override 3MF-embedded settings; flags track setting keys (layer_height -> --layer-height); Linux may need `xvfb-run`; flags have shifted between versions — [Printago Orca CLI reference](https://printago.io/blog/orca-slicer-cli-reference), [OrcaSlicer CLI mode](https://www.orcaslicer.com/wiki/cli/cli_mode). Where Orca puts time/filament stats was not confirmed (likely in the sliced 3MF/G-code).
- OrcaSlicer's `--mtcpp`/`--mstpp` defaults give ready-made guard rails (triangle count and slice-time timeouts) for a public upload endpoint.

**Mesh-based estimation and validation**
- trimesh 5.2.0: loads STL (binary/ASCII), OBJ, PLY, GLTF/GLB, 3MF (needs lxml), 3DXML; `mesh.is_watertight`; volume, centre of mass, inertia; axis-aligned and oriented bounding boxes (`bounding_box.extents`); fixes simple winding/normal/hole problems; `mesh.split()` into bodies; only hard dependency is numpy; license not shown on the page (it is MIT per my recollection, not verified) — [trimesh docs](https://trimesh.org/).
- Quoting widgets that compute from volume alone: Zbotic describes its estimate as an instant ballpark from model volume; its price panel shows size, volume and surface area; if auto-quote fails it shows a reason and an email option for a manual quote — [Zbotic 3D printing service](https://zbotic.in/3d-printing-service/), [Zbotic guide snippet](https://zbotic.in/custom-3d-printing-service-india-guide/).
- IamRapid's instant quote analyses the STL (sample shows volume 83 cc and weight 102.92 g -> implies ~1.24 g/cc PLA density, arithmetic on cited numbers) — [IamRapid pricing](https://iamrapid.com/pricing/).
- Self-described accuracy: Slicepress author claims slicing-based quotes match what you would get opening the file in OrcaSlicer; auto-orientation "good but not perfect"; a selfcad review notes the slicer will always be most accurate for a specific print (snippet-level) — [Printables article (snippet only, fetch 403)](https://www.printables.com/article/slicer-api-with-wordpress-plugin-that-creates-inst-n5jba25), [selfcad](https://www.selfcad.com/blog/3d-printing-cost-calculator).

**Existing quote engines and their architectures**
- Slicepress: GPL WooCommerce client; hosted backend running a modified containerised OrcaSlicer; STL/3MF upload on product page; backend not open source — [Printables article (snippet only)](https://www.printables.com/article/slicer-api-with-wordpress-plugin-that-creates-inst-n5jba25).
- Birlo 3D Print Lite v1.0.11 (Published 25 Sep 2026, <10 installs, no reviews): built-in geometric estimator for STL/OBJ; optional local CuraEngine/OrcaSlicer "installed and configured by the site owner"; build-volume and manufacturability checks; 3MF excluded from auto-quote; one FDM printer only (resin blocked in Lite); models stored via WordPress upload handler in private storage — [Birlo](https://wordpress.org/plugins/birlo-3d-print/).
- PrintPrice v1.8.0: cloud service parses mesh for volume/mass/time; uploads go browser -> AWS S3 Frankfurt (not through WP server); sliced Bambu Studio 3MF/G-code give real time, otherwise estimated from filament mass; experimental support estimate; STL, OBJ, 3MF, STEP/STP; OBJ/STL need user-chosen units — [PrintPrice](https://wordpress.org/plugins/printprice-3d-calculator/).
- WP3DP/3DPrint: infill, support and print time calculated by Cura 3.4 on a remote server (30 free API calls/month with one-time purchase; subscription for unlimited and for per-hour pricing); model repair via Slic3r; formats 3MF, STL, OBJ, STP, IGES, DXF, SVG, ZIP; changelog lists WooCommerce 11 compatibility — [wp3dprinting.com](https://wp3dprinting.com).
- SliceQuote: hosted iframe widget from slicequote.de, STL/3MF/OBJ, binding price with its own ordering/payment, free plan, <10 installs, no WooCommerce mention — [SliceQuote](https://wordpress.org/plugins/slicequote/).
- Open-source calculators found (not opened; licence/maintenance unverified): estimate3d (apbetioli), Solo-Web-Works/3D-Print-Estimator, PolymagicPrice (FDM+resin, quote management), 3dpcalc, alexeygrek/stl-calc; Python `fdm-price-calc` (CLI + library, parses PrusaSlicer output) — [search results](https://awesome.ecosyste.ms/projects/github.com%2Fapbetioli%2Festimate3d), [PolymagicPrice](https://gh.r-mj.com/RPHobbyist/PolymagicPrice), [fdm-price-calc](https://pypi.org/project/fdm-price-calc/). No self-hostable, maintained "slicer API + WP plugin" open-source pair was found; the Prodaxis Print Quote plugin calls a separate (apparently proprietary) gateway with `/slicer/upload` — [Prodaxis](https://wordpress.org/plugins/?p=334513).

### Inferences
- Recommended architecture for Akrinity: WordPress/WooCommerce (PHP) stays the storefront; a small Python (FastAPI) microservice on a VPS does: (1) upload with size/extension limits, stored outside web root with random names; (2) trimesh load -> `is_watertight`, volume, bounding box, triangle count, split bodies; (3) instant "volume x infill/shell factor x density" estimate (seconds); (4) optional queued headless slice (PrusaSlicer or OrcaSlicer, with `timeout`/triangle caps) returning grams and minutes parsed from G-code; WordPress gets results via REST with a shared secret and caches by file hash. PHP should not shell out to the slicer directly from web requests (timeouts, security).
- Practical accuracy ladder: volume-only is cheap but misses supports, infill pattern and slow-print time; calibrate with a few sliced reference parts to fit time ~ a + b x volume + c x surface area (my suggestion, not a sourced method), and quote slicer-based only for final "confirmed price" after the instant estimate, or label the instant number "estimate, final price confirmed within 24 h" like Zbotic's manual fallback pattern.
- Resin (MSLA) quoting differs: time depends on Z-height (layers) not volume, so use bounding-box height x layer time plus per-ml resin; PrusaSlicer's `--slice` supports SLA via `printer_technology`, but no source describes Indian resin-printer profiles.
- Client-side three.js/trimesh-js volume computation (signed tetrahedron volume from triangles) is feasible for a preview-only estimate but has no cited support; keep server-side validation authoritative, since browser values are user-controlled.
- Plugin fit: 3DPrint Lite is stale-looking (not tested with last 3 WP majors) and has no WooCommerce; paid WP3DP and PrintPrice (cloud dependency, customer files leave your server) are faster but create vendor/data lock-in; Birlo/SliceQuote are too new and low-install; a custom microservice gives control and keeps files in India.

### Gaps
- No official PrusaSlicer CLI wiki page content retrieved; exact G-code comment strings for PrusaSlicer 2.9.x/OrcaSlicer must be verified on a sample file (including whether Orca CLI writes `; total filament weight` etc.).
- CuraEngine CLI usage was not researched (no source fetched).
- No benchmarked accuracy numbers (volume estimate vs slicer) found.
- No sourced treatment of client-side three.js quoting or STL repair thresholds.
- Open-source repos were not opened, so licences/maintenance unverified.

## 3. Existing WooCommerce/WordPress plugins (3D print quoting and file-upload quotes)

### Takeaway
Purpose-built options: WP3DP/3DPrint (premium, long-lived, WooCommerce integration, remote Cura slicing), PrintPrice (free tier up to 5 paid orders/mo, cloud-parsed, approval/counter-offer quote flow), and several very new low-install plugins (Birlo, SliceQuote, Slicepress). Generic request-a-quote plugins (YITH, Addify, WebToffee etc.) handle quote-to-order but have no mesh analysis. For a custom build, the useful ideas are PrintPrice's "approved quote becomes a WooCommerce product/cart item" and YITH's "quote as an order with statuses".

### Cited Findings
- 3DPrint Lite (WP.org): free; v2.1.9, modified 17 Sep 2026, 600+ installs, 4.8/5 from 37 reviews, published 2015; WP 3.5+; flagged as not tested with the latest three WP majors/possibly unmaintained; STL/OBJ/ZIP only; WooCommerce, STEP/IGES/DXF, infill/support/per-hour pricing, repair, discounts are premium-only — [3DPrint Lite](https://wordpress.org/plugins/3dprint-lite/).
- WP3DP premium: one-time plugin purchase includes updates and free support for one website plus 30 free API calls/month; subscription removes limits and is needed for per-hour pricing; first 30 models free; USD price not stated on the page; WooCommerce 3.0+; Multi Currency and WPML; passes dimensions/weight to shipping plugins; security: v4.5.4.1 added SVG sanitisation, optional form nonces (Settings -> Other -> Security); billing via 2Checkout — [wp3dprinting.com](https://wp3dprinting.com). Page inconsistently lists slicers (Orca/Bambu/Anycubic/Slic3r/Cura vs Prusa/Cura/Slic3r).
- PrintPrice v1.8.0: 10+ installs, 1 five-star review; free plan includes all features but limits to 5 paid orders/month, paid tiers Basic 50 / Pro 100 / Business 300 paid orders per month via Freemius (prices not listed); needs WooCommerce REST read/write keys; quotes can require approval, counter-offers, decline with reason, PDF quotes, saved-quote reminders; approved quotes enter the cart as normal WooCommerce products so gateways/shipping/tax apply; files in AWS S3 Frankfurt, deleted within 7 days after order deletion; customer IP/email/files processed by PrintPrice Cloud; 18 languages — [PrintPrice](https://wordpress.org/plugins/printprice-3d-calculator/).
- Birlo and SliceQuote details as in section 2: both <10 installs; Birlo includes job workflow statuses, inventory lots, maintenance calendar and customer job area; its support shows 0 of 1 issues resolved in two months — [Birlo](https://wordpress.org/plugins/birlo-3d-print/), [SliceQuote](https://wordpress.org/plugins/slicequote/).
- Other 3D-quote plugins surfaced (not evaluated): Prodaxis Print Quote, SeekMake, 3D Print Pricing Calculator, Slice & Price (Shopify) — [Prodaxis](https://wordpress.org/plugins/?p=334513), [SeekMake](https://wordpress.org/plugins/seekmake/), [3D Print Pricing Calculator](https://wordpress.org/plugins/3d-print-pricing-calculator/), [Slice & Price](https://apps.shopify.com/slice-and-price).
- YITH Request a Quote: free version already has a status-based workflow where a quote request is managed as an order and its status changes when the customer accepts; premium adds quote button on more pages, quotes as orders with expirable proposals, automation. Competitors Addify and WebToffee advertise converting approved quotes to orders. No YITH price found — [YITH on WP.org](https://wordpress.org/plugins/yith-woocommerce-request-a-quote/), [WebToffee](https://www.webtoffee.com/yith-woocommerce-request-a-quote-plugin/), [Addify](https://addify.store/product/woocommerce-request-a-quote/).
- WooCommerce deposit plugins for advance + balance (see section 5): PH Deposits and Partial Payments, Vanquish Deposits, DatRooster, Halfway, Advanced Partial Payment, official WooCommerce Deposits — [PH Deposits docs](https://woocommerce.com/document/ph-deposits-and-partial-payments/).

### Inferences
- Plugin-security watch points for any file-upload quote plugin: restrict extensions (STL/3MF/OBJ/STEP, not SVG unless sanitised), upload size caps, store outside web root, nonces, auto-delete of stale files. WP3DP's own changelog shows SVG sanitisation was only added at v4.5.4.1, indicating that class of risk is real.
- Fit with custom build: buying WP3DP gives the fastest launch but ties per-hour pricing and print-time estimates to a subscription and a remote Cura 3.4 (old); a custom stack lets you use modern Orca/Prusa profiles and Indian pricing rules (GST, INR, advance payment).
- Hybrid option: use YITH/Addify only for generic "request a custom design" RFQs (non-mesh) and build the mesh quote engine custom.

## 5. Order status pipeline in WooCommerce (statuses, emails/WhatsApp, quote -> payable order, advance + balance, data model, HPOS)

### Takeaway
Register statuses with `register_post_status('wc-xxx')` plus the `wc_order_statuses` filter (slug including `wc-` must be <= 20 chars, so <= 17 chars after prefix), declare HPOS compatibility and use only order-object APIs. Represent an approved quote as a real WooCommerce order in a custom pending-style status and send the customer its order-pay URL; handle advance + balance either with a deposits plugin (parent order "partially paid") or with two linked orders/fees. Hook `woocommerce_order_status_changed` for emails and WhatsApp.

### Cited Findings

**Custom statuses and HPOS**
- Statuses are WordPress post statuses prefixed `wc-`: register with `register_post_status()` on `init`, then add to the `wc_order_statuses` filter; `$order->get_status()` returns the slug without `wc-` while DB, `register_post_status()` and `wc_order_statuses` use it — [Cloudways tutorial](https://www.cloudways.com/blog/create-woocommerce-custom-order-status/) (third-party), [community gists](https://gist.github.com/claudiosanches/e68e891d593c4c989d9d).
- Order statuses are stored in varchar(20) including `wc-`; a longer custom slug is silently truncated on save and the order then drops out of status queries (issue reported on WC 11.2.1, so keep slugs <= 17 chars); statuses register at `init` priority 9 (PR discussion) — [WooCommerce issue #70266](https://github.com/woocommerce/woocommerce/issues/70266), [PR #68590](https://github.com/woocommerce/woocommerce/pull/68590).
- `wc_get_orders()` accepts statuses with or without `wc-`, case-insensitive; if none requested are known no orders return; HPOS custom query vars via `woocommerce_order_query_args`, legacy via `woocommerce_order_data_store_cpt_get_orders_query`; use `OrderUtil::custom_orders_table_usage_is_enabled()` to branch — [WooCommerce wc_get_orders docs](https://developer.woocommerce.com/docs/extensions/core-concepts/wc-get-orders/).
- HPOS compatibility: declare via `FeaturesUtil::declare_compatibility('custom_order_tables', __FILE__, true)` inside `before_woocommerce_init`; do not use `get_post()`/direct postmeta on orders (use `wc_get_order()` and `update_meta_data()`/`add_meta_data()`/`delete_meta_data()` then `save()`); with HPOS orders live in dedicated tables, not wp_posts/wp_postmeta — [WooCommerce HPOS recipe book](https://developer.woocommerce.com/docs/features/high-performance-order-storage/recipe-book/).
- HPOS admin bulk actions use `bulk_actions-woocommerce_page_wc-orders` and `handle_bulk_actions-woocommerce_page_wc-orders`; `woocommerce_register_shop_order_post_statuses` is used in tutorials to set label/visibility flags (not confirmed in official docs) — [Tyche Softwares tutorial](https://ww2.tychesoftwares.com/?p=686352) (third-party).

**Emails and notifications**
- Hooks for status emails: generic `woocommerce_order_status_changed` (old/new status), transition hooks such as `woocommerce_order_status_pending_to_processing_notification`, status hooks `woocommerce_order_status_{status}`; Tyche registers the custom status in `woocommerce_email_actions` and calls `send_transactional_email` on `woocommerce_order_status_wc-{status}` (exact hook naming for custom statuses was not confirmed — verify); a WordPress.org thread reports `woocommerce_order_status_changed` not firing for one gateway's orders — [Business Bloomer](https://www.businessbloomer.com/woocommerce-send-order-email-custom-status-transition/), [WooCommerce docs on email](https://woocommerce.com/document/sending-email-notifications/), [WP support thread](https://remarpro.com/support/topic/new-order-status-changed-but-woocommerce_order_status_changed-not-fired).
- WhatsApp Business API: Meta charges per delivered template message by category and country since 1 Jul 2025; India utility rate is Rs 0.115 (Telecrm, Hyperleap) vs Rs 0.145 (AiSensy) — sources conflict; marketing Rs 0.78-1.09 (also conflicting); BSP fees and GST extra; AiSensy says billing for service messages starts from the 1,001st delivered message under an October 2026 change — [AiSensy Oct 2026 update](https://m.aisensy.com/blog/whatsapp-pricing-update-october-2026/), [Telecrm](https://telecrm.in/blog/whatsapp-business-api-pricing/), [Baat.ai](https://baat.ai/blog/whatsapp-api-pricing-india). Meta's official rate card was not retrieved.

**Quote -> payable order**
- `WC_Order::get_checkout_payment_url($on_checkout=false)` returns the pay URL for an unpaid (pending) order, pattern `/checkout/order-pay/{order_id}/?pay_for_order=true&key={order_key}`; the order key secures the link; filter `woocommerce_get_checkout_payment_url`; admins can surface it on the order screen (e.g. `woocommerce_admin_order_data_after_order_details`); a Square thread reports the Square form failing on the order-pay endpoint, so test each gateway (Razorpay etc.) — [wp-kama reference](https://wp-kama.com/plugin/woocommerce/function/WC_Order::get_checkout_payment_url), [Metorik help](https://help.metorik.com/article/162-order-payment-url-doesnt-work), [Square community](https://community.squareup.com/t5/Payments-Troubleshooting/WooCommerce-and-Square-Order-Pay/td-p/790947).
- PrintPrice's approach: approved quote is created as a WooCommerce product added to the cart, so standard gateways/tax/shipping apply; YITH's approach: quote request is an order whose status changes when the customer accepts — [PrintPrice](https://wordpress.org/plugins/printprice-3d-calculator/), [YITH](https://wordpress.org/plugins/yith-woocommerce-request-a-quote/).

**Advance + balance payments**
- WooCommerce has no built-in partial payment setting; without a plugin you create a separate order per part payment manually — [Halfway plugin](https://wordpress.org/plugins/halfway-deposits/).
- Plugins: Vanquish Deposits adds a "Partially paid" status (or map to Processing/On hold), shows Paid/Balance due and a Pay now page; PH Deposits lets you choose the parent order status after final payment (Partially Paid, Processing, Completed); DatRooster (development-stage) auto-completes the parent when the linked balance order is paid; official WooCommerce Deposits marks the original order processing or partially paid; one reviewer says Advanced Partial Payment allowed deposit but not balance in an older version — [Vanquish](https://wordpress.org/plugins/?p=389077), [PH Deposits](https://woocommerce.com/document/ph-deposits-and-partial-payments/), [DatRooster](https://wordpress.org/plugins/datrooster-partial-payments), [WooCommerce Deposits](https://www.woocommerce.com/products/woocommerce-deposits/).

### Inferences
- Suggested status slugs (all <= 17 chars after `wc-`): `wc-quote-req` (Quote requested), `wc-quote-sent`, `wc-quote-appr` (Approved), `wc-await-adv` (Awaiting advance), `wc-queued`, `wc-printing`, `wc-post-proc`, `wc-qc`, `wc-ready-ship`; reuse core `wc-processing` for "advance received", `wc-completed` for delivered, `wc-on-hold`, `wc-cancelled`, `wc-refunded`. Core `pending`/`on-hold` also gate order-pay (pending statuses are payable by default; confirm for custom statuses via `woocommerce_valid_order_statuses_for_payment`, which I recall but did not source).
- Pipeline: quote requested -> quote sent (price + expiry) -> approved by customer -> awaiting advance (order-pay link) -> advance paid (processing) -> queued -> printing -> post-processing -> QC -> awaiting balance (if balance due before dispatch) -> shipped (tracking meta) -> delivered/completed; side exits: expired, rejected, failed-print reprint, cancelled, refunded.
- Quote entity choice: (a) quote as a WooCommerce order from the start (draft/custom-status order created via `wc_create_order()`, with line items = print job) gives one record, built-in payment links, admin UI, HPOS storage and emails; (b) a separate quote CPT/custom table keeps non-purchased quotes out of order reports/analytics and avoids polluting WooCommerce stats, then converts to an order on approval. Recommended hybrid: store files/analysis/pricing snapshots in a custom table keyed by quote ID (with price breakdown JSON, file hash, tech, material, dimensions, volume, grams, minutes, validity), and create the WooCommerce order only on approval so unapproved quotes never appear as orders; link via order meta (`_quote_id`) using only `$order->update_meta_data()`.
- Advance + balance: simplest robust pattern for a small shop is two orders (advance order + balance order) linked by meta, with the parent as the job record and status `awaiting balance` before shipping; or use a deposits plugin for the "partially paid" semantics. Whichever route, test Razorpay on order-pay.
- Notifications: queue a WhatsApp utility template (Rs 0.1-0.15/msg + BSP markup) on `woocommerce_order_status_changed` for key milestones (quote ready, payment received, shipped with tracking) and keep email as the fallback; do not send to every internal status.
- Data model: keep print-job fields (file, material, layer height, infill, grams, minutes, QC checklist, tracking) as order item meta or order meta (HPOS-safe via CRUD) or in a custom table `{prefix}akr_print_jobs` linked to order ID; use a custom table for high-volume event logs (status history, QC checks), CPT only for non-order records like quotes if you reject the custom table.

### Gaps
- Official WooCommerce docs for registering custom statuses and for custom status email hook naming were not retrieved (tutorials only).
- Whether custom statuses are payable via order-pay by default was not confirmed from source.
- Official Meta WhatsApp rate card and Razorpay-specific order-pay behaviour were not checked.
- No Indian GST rules for advance payments (time of supply, invoicing of advances) were researched.
